# 项目品牌配置重试 worker

代码入口为 `POST /api/internal/visibility/context-sync`。每次最多处理3个项目的最早未确认版本，每项目最多1次15秒请求，失败按30秒起的指数间隔延后，最多1小时。相同版本与内容幂等，未知结果保留；没有模型请求或采集额度消耗。权限撤销或项目不存在时不投递，管理员仍可从页面显式重试。

在预发布/生产运行环境配置 `VISIBILITY_CONTEXT_SYNC_SECRET`（独立强随机共享密钥）及 `VISIBILITY_CONTEXT_SYNC_ORIGIN`（同机Nginx入口地址）。不要把密钥写入仓库、命令参数、日志或镜像。默认origin是同机127.0.0.1 HTTP入口，部署时应核实实际可用路由，不直接绑定蓝绿槽端口。

使用Node18+运行 `node /opt/genilink-platform/deploy/context-sync-worker.mjs`，通过现有调度器每分钟调用一次，任务环境读取正式运行配置。脚本55秒超时且只记录状态/处理数量，不输出请求头、响应正文或密钥。调度器及密钥需通过正式预发布和发布配置落地，本次只新增脚本与接口，未在服务器安装定时任务。

验收：预发布配置专用密钥后，模拟远端不可用，确认outbox保留并延后重试；恢复服务，确认按版本回执hash一致后ack。撤销创建人权限后不发服务token；管理员页面重试可恢复积压。同项目并发调度可能重复投递，接收端版本幂等保证配置不重复生效；不声称仅发一次请求。真实PG/MySQL行锁、源配置变化与最后一项解绑的空配置必须联调。

所有表结构只生成迁移文件，未执行真实迁移。初始品牌、关联和配置现在同一事务提交并校验注册额度；项目创建本身独立提交，品牌配置未成功时响应brandConfigurationPending=true，用户可在项目管理继续配置。项目专属角色/实体ID绑定仍未接入。
