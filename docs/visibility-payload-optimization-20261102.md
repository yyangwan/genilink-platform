# 可见性采集页响应体积优化

2026-11-02，用户通过浏览器确认 `/visibility` 会先读取约 2MB 的 dashboard，再为四个下拉菜单串行读取约 6MB 的完整 run detail，分别等待约 14 秒和 15 秒。

同一条生产数据的只读剖析结果（UTF-8 JSON 字节数，不记录业务原文或身份信息）：

| 响应 | 后端读取耗时 | 响应字节数 | 主要内容 |
| --- | ---: | ---: | --- |
| run detail | 0.377 秒 | 6,062,737 | 完整评分、品牌观察、诊断、机会与证据 |
| dashboard overview | 0.335 秒 | 2,101,092 | 诊断、机会、完整指标分母和实体 |

这些读取耗时不包含浏览器链路、前端鉴权、代理序列化和下载耗时，不能等同于页面加载耗时。先前健康检查不能覆盖这类业务响应问题。

## 修改

- 采集页显式请求 `dashboard?view=collection`。工作台默认 overview 契约不变。
- collection 只返回最新审计、最新修订及其新鲜度、采集/分析计数、冻结的品牌与平台选项。不重建证据指标、不返回评分矩阵、诊断、机会、来源或原文。
- 比较栏直接使用这次响应的选项，移除采集页对 `intelligence?view=detail` 的调用。审计洞察的完整分析数据不截断。
- 同一次审计、同一修订、项目权限、基础版字段白名单、配置待同步状态与四项选择跨页保留的逻辑继续生效。

## 回归验证

- 后端用超过 3MB 的合成分析数据验证 collection 响应小于 4KB（小规模品牌样本），并禁止调用完整指标/证据重建函数。
- 验证当前/过期快照、未知视图、跨项目访问和未生成分析的状态。
- 页面测试使用内嵌选项驱动四个下拉框；任何完整 detail 请求都会失败，且测试确认不存在该请求。
- 实际生产响应大小随品牌选项数量变化，最终上线后需针对原项目复测；不把合成样本的 4KB 当作生产数据体积。
