## 引用文章真正保存了什么

最初十次来源抓取均被 SSRF 检查拒绝：本机 DNS 返回 198.18.x / 2001:2:: 等非公网地址，未发出正文 HTTP 请求。没有削弱 SSRF 检查、修改系统 DNS 或生产配置。

随后仅在隔离验收 worker 进程中，以实时公网 DNS 查询替换解析适配，仍执行原有公网地址校验、地址固定、TLS、重定向和大小上限。127.0.0.1、公私混合解析与 198.18.x 的拒绝验证均通过。原十条 blocked 记录保留，新建明确的测试重试任务。查询协议参考 [Cloudflare 官方 DNS JSON 文档](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。此适配只解决本机验收网络，不是新增生产 DNS 方案。

- 十个来源中九个产生可读正文快照，一个 empty_content。
- 九份原始 HTML 与正文压缩对象均经保存校验和复验，正文内容哈希一致。
- 保存正文共 76,463 字符、96 个证据分段；每个分段都核对保存正文中的精确范围。
- 保存质量为 text_available；文章全文完整性仍 unknown，不能把 HTTP 200 或有正文当成全文完整。
- 本轮使用本地不可变对象存储；没有写入或验证真实 OSS。

## 真实模型分析与质量边界

冻结同一真实材料的新修订，调用官方 api.deepseek.com 的 deepseek-v4-flash，没有经过 Higress。一次瞬时连接错误后继续原任务，最终 job=succeeded、run=partial。预算账本记录 26 个请求预占、88,018 charged tokens；其中含连接错误的保守未知用量预占，不是精确账单。

实际保存 50 个实体候选、87 个声明候选、3 个诊断。分析覆盖记录同时保留：108 个总分段、17 个 processed（7 completed、10 partial）、90 deferred、1 failed；111 个原文范围被拒绝，1 个语义错误，来源对齐 checked_pairs=0。这里的 108 包括回答等材料，不等于 96 个文章分段。不能把处理过的分段等同于完成分析，也不能把候选结果当成已证实主张或高价值建议。

旧千问来源种类为 unknown，无法冒充已核验的回答引用关系。后续必须用修复后的生产者重新采集，并独立复核候选身份、原文范围、声明支持、平台差异和可执行建议，再评估质量与实际价值；不回填旧封存事实。
