# 智链微信小程序首版开发方案

2026 年 11 月 13 日 · 对应[首版产品方案](./wechat-mini-program-acquisition-mvp.md)

## 交付范围

微信用户能匿名检查一个公开官网首页，看到页面证据和可执行建议。点击「保存结果并继续」后，已有用户验证并关联原智链账号，新用户验证手机号并确认开户。小程序和电脑网页能打开同一份已保存报告。用户可从报告发起完整官网诊断，或主动申请品牌实测。分享入口以用户主动转发小程序入口卡片为主。

首版采用微信原生小程序、TypeScript 和现有智链后端。新用户优先使用微信手机号一键开户，短信验证供已有账号及无法使用微信授权的用户选择。小程序内网页免登录作为可独立开启的增强项。公开快检采用确定性规则，完整官网分析和品牌实测继续使用原有业务流程。

## 系统分工

| 系统 | 开发位置 | 责任 |
| --- | --- | --- |
| 微信小程序 | 本仓库新增 `apps/wechat-mini-program/`，独立依赖与类型检查 | 官网输入、等待和结果、身份验证、已保存报告、深测申请。使用原生 `wx.request` 和 `wx.login`，配置按环境区分 |

| 可见性分析服务 | 相邻仓库 `geo-visibility-analyze/backend/app/` | 增加仅供智链调用的单页快检入口，复用安全抓取与 HTML 解析，返回有据可查的检查结果 |

现有正式诊断接口需要项目和工作区，并执行计费预留。匿名检查增加独立服务接口，复用分析服务里的 `intelligence/sources.py` 公开抓取能力和 `product_website_analysis_service.py` 的 `extract_page`。现有安全抓取已逐跳校验，默认总时限 30 秒且只接收未压缩响应。开工时先验证可否提取共用抓取函数并传入快检专属参数，保持现有引用来源采集的默认行为。用真实样本站点测量压缩响应和脚本渲染对可用率的影响。 [正式分析启动逻辑](../../src/lib/product-website/start-analysis.ts) · [原有获客流程](../../src/app/api/acquisition/activate/route.ts)

## 01 · 匿名官网快检

1. 小程序取得随机访客凭证并保存到本地。服务端只保存摘要，复用 `AcquisitionSession` 记录来源。提交网址时带 `Idempotency-Key`。每次用户明确发起新检测生成新键，重试沿用旧键。
2. 智链校验网址并建立报告记录，以受限并发发起一次有总时限的分析服务调用。首版采用请求内执行。同一访客、同一键、相同请求返回已存在的报告或 `202`。同一键换网址返回 `409`。客户端重进时通过报告 ID 恢复。尚未拿到 ID 或租约过期时用原键重新提交。旧执行者无法覆盖新执行者的结果。
3. 分析服务只接收一个标准化的公开 HTTP/HTTPS 首页。默认只访问该页，允许有限次正常重定向。抓取层校验实际连接目标和每次跳转，限制内容类型、解压后体积和总时长，不携带用户 Cookie 或其他站点凭证。建议初值为最多 3 次重定向、2 MiB 解压后内容、上游总预算 10 秒、客户端等待上限 20 秒。用现有固定窗口限流做访客、来源 IP 和目标域约束，再加全局并发上限。并发满时给出可重试状态。
4. 输出三组检查项。首页是否可访问，HTML 中是否有清晰的标题和可提取的正文，页面是否声明可解析的 JSON-LD。证据包括标题、受限长度的正文摘录或结构化类型。对于只看到脚本壳、站点拦截或证据不足的页面，返回 `unknown`，避免推断站点没有业务内容。建议按问题优先级选一条。结果携带检查时间、规则版本、输入与最终域名。展示一律用纯文本。

上游内部接口建议为 `POST /api/internal/website-quick-check/v1`，请求字段为 `requestId`、`url`。用独立的服务间凭证和既有内部网络配置隔离此入口。上游保持无状态，智链持久化报告并掌握重试和用量。首版用 20 个以上真实公开首页校准。可用率以代表性样本统计，P90 从点击到首份有可核对证据的结果，以 20 秒为体验目标，分别记录抓取失败和浏览器端等待。

## 02 · 微信身份、短信和账号关联

| 场景 | 实现 |
| --- | --- |
| 已绑定 | 在用户保存或查看历史时，后端用 `wx.login` 的 code 换取小程序身份，查找 `(AppID, OpenID)`，向原 `User.id` 签发小程序会话 |
| 首次关联已有手机号账号 | 创建 10 分钟绑定流程，短信挑战绑定该流程和规范化手机号。服务端验证后显示脱敏手机号和关联确认，确认时关联原账号 |
| 新手机号开户 | 用户接受智链协议并授权微信手机号后，服务端使用绑定流程里的 OpenID 向微信兑换手机号，校验小程序 AppID，再原子创建用户、身份绑定、同意记录和会话。短信方式仍可开户 |
| 历史公众号无手机号账号 | 进入「关联已有智链账号」。电脑端用原账号登录并再次证明账号归属，生成绑定该网页账号的短时二维码。小程序扫码、验证待绑定手机号并确认后，将手机号和微信身份一并绑定到原账号。若原登录方式未启用或凭证不足，引导现有账号支持流程 |
| 微信身份和手机号指向不同账号，或历史记录有手机号重复 | 阻止写入并记录冲突类型。返回账号恢复入口，保留已有工作区、项目和权益 |

选择新增专用 `MiniProgramIdentity`，用数据库同时约束 `(appId, openId)` 和 `(appId, userId)`。公众号身份继续按现有入口处理。UnionID 可用于判断是否需要走原账号关联流程，具体绑定仍以已验证凭证为准。小程序会话用服务端可撤销、可过期的独立凭证。退出登录会撤销会话。私有报告访问始终以服务端身份为准。

复用现有短信提供商、频控和手机号规范化。将验证码验证与「查找或创建用户」拆开，小程序验证码独立用途并限定到对应绑定流程。验证码消费后留下短时绑定证明，以便用户确认和安全重试。Web 短信登录和小程序开户使用同一手机号解析策略，覆盖 `+86` 规范值和历史裸号码。两处并发开户以规范化手机号串行，数据库唯一约束作为最后一道保护。上线前先在只读检查中识别历史重复组，个别冲突进入恢复流程。

每次确认绑定时在事务内重查微信和手机号归属，并原子消费确认凭证。并发提交必须收敛为同一账号或一个可解释的冲突。未知的微信登录结果允许重新发起 `wx.login`。拒绝验证或验证失败时，访客仍可看原快检。 [现有短信登录](../../src/lib/auth/sms-verification.ts#L91) · [手机号处理](../../src/lib/auth/phone.ts) · [账号模型](../../prisma/schema.prisma#L12) · [腾讯云小程序登录接口说明](https://cloud.tencent.com/document/product/1441/68677)

## 03 · 报告归属和跨端承接

- **保存。** 用小程序会话和创建报告时的访客凭证认领。更新条件同时校验归属、报告状态和有效期。首次成功绑定至 `User.id`，同一用户重试返回同一报告。认领后仅报告归属账号能读取。登出或切换账号时清空本地私有数据并更换访客凭证，防止同一手机上的账号共享上次使用上下文。
- **跨端。** 电脑端登录后，通过工作台「官网快检」打开 `/quick-checks`，直接按 `User.id` 查询个人报告，即使还未创建工作区也能查看。若业务域名和真机验证通过，小程序可用同域 `web-view` 进入移动报告页。网页会话通过绑定用户及报告的一次性凭证和 Auth.js 建立，避免携带长效登录凭证，兑换后跳转至干净地址。遇到 WebView 已登录不同用户时，要求显式确认切换。原生报告和电脑登录路径独立可用。
- **继续诊断。** 由网页承接「做完整官网诊断」。内嵌网页可用时可在微信里继续，否则小程序提示到电脑登录智链，从「官网快检」打开该报告。进入诊断时选择工作区和项目，服务端按现有项目权限、可用额度及成员身份校验，匹配可用项目或明确创建个人工作区及项目。已有项目的网址和品牌资料按现有编辑权限处理。确认后调用正式诊断，并以稳定的操作键复用已启动记录。上游结果暂不明确时，显示处理中并按现有对账逻辑恢复。用户保存报告时不会启动正式任务。
- **申请品牌实测。** 登录后提交品牌、品类或业务场景、可联系渠道及单独的联系同意。新增 `brand_visibility_check` 线索类型，复用现有联系方式加密、撤回、运营处理。首版以人工承接。测试提交进入测试运营队列。

分享卡片带有限长度、受服务端识别的渠道参数，落到自己的快检入口。后续如开放摘要分享，使用独立可撤销的公开凭证。 [现有项目接口](../../src/app/api/projects/route.ts) · [线索处理](../../src/lib/marketing/leads.ts) · [网页认证](../../src/lib/auth/config.ts) · [腾讯云业务域名指南](https://cloud.tencent.com/document/product/1301/100434)

## 04 · 接口和数据契约

除网页配对页面外，以下路径均相对于 `/api/mini-program/v1`。接口以稳定 `code` 表示错误，使用 `Cache-Control: no-store` 保护凭证和私有结果。小程序独立会话和访客凭证分别传入鉴权头，Web 使用 Auth.js Cookie。

| 接口 | 调用权限与输入 | 返回或变更 |
| --- | --- | --- |
| `POST /visitor-sessions` | 匿名，已有访客凭证可复用，入口渠道 | 访客凭证和有效期 |
| `POST /quick-checks` | 访客，`url`、幂等键 | `201` 新报告完成，`200` 已有结果，`202` 正在执行，`429` 限流 |
| `GET /quick-checks/{id}` | 原访客或已保存的账号 | 报告、当前状态和可重试标记。跨账号访问返回 `404` |
| `POST /auth/wechat/exchange` | 微信临时 code | `signed_in` 和小程序会话，或 `verification_required` 和短时流程凭证 |
| `POST /auth/binding/sms/send`、`/verify`、`/confirm` | 绑定流程凭证、手机号或验证码、确认项 | 验证、关联确认或开户确认、绑定后的会话。错误码涵盖验证码失效、身份冲突、确认过期 |
| `POST /auth/binding/wechat-phone` | 绑定流程凭证、微信手机号授权码、协议确认项 | 未注册手机号开户并签发会话。已注册手机号提示验证原账号 |
| `POST /auth/binding/pair/confirm` | 小程序绑定流程、网页签发的一次性配对凭证、验证过的手机号证明 | 关联经过网页侧重新验证的原账号 |
| `POST /quick-checks/{id}/claim`、`GET /me/quick-checks` | 小程序会话。认领时另验访客凭证 | 幂等保存或游标分页的个人报告列表 |
| `POST /quick-checks/{id}/view` | 原访客或报告归属人，结果首次渲染后调用 | 按报告 ID 记录首次查看，重复调用返回成功 |
| `POST /quick-checks/{id}/brand-assessment` | 报告归属人，品牌、场景、联系同意和幂等键 | 申请回执及联系授权撤回入口 |
| `POST /auth/logout` | 小程序会话 | 撤销当前会话 |

网页使用同一领域服务实现配对、报告查询及完整诊断发起。网页配对从登录后的账号页发起，使用现有登录方式重新验证，服务器签发一次性挑战。小程序和网页同时展示可核对的脱敏账号，用户确认后服务端原子兑换。网页以 `POST /api/quick-checks/{id}/full-diagnosis` 接收明确选定的工作区、项目或创建选项，由服务端解析报告网址与正式诊断操作键。若启用 WebView，再增加专用的签发与兑换接口。

| 数据 | 最小字段与约束 |
| --- | --- |
| `WebsiteQuickCheck` | `id, acquisitionSessionId, ownerUserId?, targetUrl, ruleVersion, status, result?, errorCode?, leaseId?, leaseUntil?, createdAt, expiresAt?`。另存幂等键摘要与请求摘要，同访客同键唯一。索引按账号和时间、过期时间 |
| 快检结果 | `checkedAt, finalHost?, checks[], priorityFinding?`。检查项含 `key, status, evidence?, action?`，状态为 `pass / issue / unknown`。任务状态为 `running / completed / failed`，可访问性异常作为可展示的检查结果 |
| `MiniProgramIdentity` | `appId, openId, unionId?, userId, boundAt`。外键到智链用户，两组唯一约束 |
| 小程序会话与短时凭证 | 服务端保存摘要、用途、所属身份或用户、有效期和消费状态。短信验证证明、网页配对、可选 WebView 兑换分用途 |
| 开户同意记录 | `userId, termsVersion, privacyVersion, acceptedAt, source`，与首次开户同事务 |
| 转化和线索 | 复用 `AcquisitionSession`、`FunnelEvent`、`MarketingLead`，用快检 ID 关联并按操作去重。快检的渠道快照在首次提交时固定 |

建议匿名报告保留 7 天，已保存报告按账号资料管理。到期清理只处理未认领报告与过期凭证，认领和清理的条件更新互相保护。日志只记录请求 ID、状态、耗时和分组后的失败码。公开输入去掉片段、凭证和跟踪参数，保留必要的首页识别信息。

## 06 · 测试与上线标准

| 验收项 | 证据 |
| --- | --- |
| 访客从微信打开并完成检测 | 有效公开站点返回页面证据，访问受限和证据不足正确区分。慢请求可恢复，重试返回同一报告 |
| 已有账号、开户和历史账号 | 预发真实微信与短信，验证前后 `User.id` 和归属。开户只出现一条用户记录，已有项目和权益保持正确 |
| 并发和授权 | PostgreSQL 集成测试覆盖同手机号并发、验证码与配对凭证只能消费一次、同报告并发认领、跨账号隔离、退出和过期 |
| 两端继续使用 | iOS、Android 小程序和电脑浏览器打开同一报告。无工作区新用户先读报告再选项目。完整诊断只在主动确认后启动，沿用配额 |
| 获取真实转化 | 测试活动能在运营页看到去重后的查看、验证、保存、正式诊断启动或实测申请。按渠道、新注册和老账号区分 |
| 公开入口承载 | 以快检样本及目标小流量压测验证耗时、成功率、限流和容量隔离。失败码可查、诊断服务过载时快检可单独关闭 |

测试分四层。分析服务 pytest 覆盖规则、边界和结果映射。智链 Vitest 覆盖路由、事务和上游错误，另外用真实 PostgreSQL 验证唯一约束。Web 用 Playwright 跑登录及报告承接回归。小程序独立类型检查和编译，最后用真实 AppID 在两类真机验证。Next.js 开工前读本仓库版本的路由与 Proxy 文档。

运营首周按报告维度计算看过报告后 7 天内的身份验证率、保存率和后续使用率。后续使用按正式诊断实际启动或有效实测申请计，同份报告去重。现有运营汇总需增加小程序事件和展示，7 天跨日转化用报告级事件关联。同步观察快检可用率、P90、微信凭证兑换失败、短信验证失败、冲突及上游过载。

## 07 · 发布与回退

1. 分析服务先合入通过测试的向后兼容版本，按该仓库既有发布流程部署私有快检接口，验证仅智链可调用且旧诊断流程正常。
2. 智链后端迁移仅做增量。新增流量入口默认关闭，建议配置 `MINI_PROGRAM_QUICK_CHECK_ENABLED`、`MINI_PROGRAM_BINDING_ENABLED`、`MINI_PROGRAM_WEBVIEW_ENABLED` 分别控制，已绑定账号的会话兑换和报告读取独立于新绑定开关。在预发布启用后做数据库兼容和鉴权验证。云端按仓库规范跑一次 `npm run release:check`，通过 PR 和 CI 部署全 SHA 镜像，验证蓝绿槽、健康检查、登录和短信回归。
3. 小程序从已合入的 Git 提交编译，使用微信开发者工具上传体验版。记录小程序版本、客户端 SHA、云端 SHA、分析服务版本与契约版本。待真机验收后提审，发布时先小流量观察。首版上传工具可手动操作，后续可接微信提供的 `miniprogram-ci`。
4. 故障时可分别停用新快检、身份关联和可选网页兑换，已保存报告继续按账号读取。云端需要回退时使用现有蓝绿回滚命令，增量数据库结构保留。小程序按微信后台的可用版本回退能力处理。移动采集网关和设备池属于独立发布范围。
