# 智链微信小程序首版方案

2026 年 11 月 13 日 · 产品与技术方案

## 首版目标

让有公开官网的小微企业主和市场运营人员，在微信里粘贴一个网址就能看到一条有依据的修改建议。用户愿意保存结果或继续分析时，可以验证身份，进入同一个智链账号，并在小程序和网页上接着处理这份结果。

官网快检作为首版功能，账号打通同时纳入首版。验证时机、手机号校验方式和网页承接方式是本方案的设计建议，需以真机验证结果定稿。

## 用户路径

| 步骤 | 用户看到什么 | 智链做什么 |
| --- | --- | --- |
| 1. 输入网址 | 粘贴官网首页，点「免费检查」 | 以访客身份发起单页检查，保留入口来源 |
| 2. 查看结果 | 一条优先建议、页面证据和具体改法 | 检查页面可访问性、公开正文的关键信息与结构化基础。证据不足时显示「暂无法判断」 |
| 3. 保存并继续 | 点「保存结果并继续」，首次使用时按提示验证手机号 | 识别小程序身份。已有智链账号完成验证后关联原账号，新用户确认服务条款和隐私政策并完成验证后创建账号 |
| 4. 打开智链 | 登录后回到刚才那份快检，看到「做完整官网诊断」 | 将这份快检保存到当前账号。用户主动开始完整诊断时，选用有权限的项目或创建项目 |
| 5. 后续使用 | 在网页或小程序打开同一份结果，继续官网诊断或申请品牌实测 | 用同一智链用户 ID 关联报告、项目和后续行为 |

授权失败、拒绝授权或退出时，用户仍可查看当前快检结果并稍后重试。若结果支持转发，分享页只展示用户主动分享的摘要，接收者可以测自己的官网。查看分享页不会获得原结果的认领权限。申请人工服务时，单独询问联系意愿。

结果页文案建议使用「保存结果并继续」，下方说明「首次使用将验证手机号并创建或关联智链账号。之后可在电脑上查看同一份结果。」

## 小程序与智链账号

小程序在用户发起保存或进入工作台时调用 `wx.login`。智链服务端用临时凭证向微信换取小程序 OpenID，并按 AppID 区分其作用域。现有 `User.wechatOpenid` 用于公众号扫码。小程序身份通过独立的账号关联记录连接到同一个 `User.id`，可优先评估复用 Prisma 的 `Account` 模型。UnionID 作为同一微信开放平台下的辅助身份信息，首版关联以用户主动验证为准。

| 情况 | 首版处理 |
| --- | --- |
| 小程序身份已绑定智链账号 | 进入原账号，保留原项目和权限 |
| 首次绑定，手机号已对应现有账号 | 复用现有短信验证。验证后确认关联原账号 |
| 首次绑定，手机号尚未注册 | 用户知悉开户并接受协议后完成验证。创建智链账号并绑定小程序身份，后续可用同一手机号登录网页 |
| 历史账号通过公众号注册且没有手机号 | 提供「登录已有智链账号」路径。用户通过现有可用方式证明原账号归属后，再绑定小程序身份及经过验证的手机号 |
| 手机号和微信身份分别指向不同智链账号，或发现历史手机号重复 | 暂停绑定，引导用户登录原账号或处理冲突。保留两边的项目和权益 |

新用户在保存报告或主动登录时，可勾选智链协议并授权微信手机号。服务端向微信兑换授权码，未注册手机号直接开通智链账号并返回原流程。已注册手机号继续验证原账号，用户也可主动选择短信验证或扫码配对。服务端复用现有手机号规范化，并按小程序绑定用途约束验证码及请求。微信一键注册由后台开通手机号快速验证并完成隐私保护指引配置后启用。

绑定、开户和结果认领各自可安全重试。绑定或开户需在事务内校验身份归属并处理唯一约束。结果认领同时验证原访客对报告的持有证明和当前登录态。认领失败时，用户可以在原页面重试保存。

依据：[智链短信认证](../../src/lib/auth/sms-verification.ts#L91)、[手机号规范化](../../src/lib/auth/phone.ts#L1)、[现有账号模型](../../prisma/schema.prisma#L12)、[公众号扫码回调](../../src/app/api/auth/wechat/callback/route.ts#L80)、[腾讯云微信小程序登录文档](https://cloud.tencent.com/document/product/1441/68677)。

## 从快检结果进入智链

- **小程序内。** 验证后原页保存，显示「在智链查看」入口。若实际主体可配置 `genilink.cn` 为业务域名且真机验证通过，用 `web-view` 打开同域的移动承接页。服务端签发绑定当前账号和报告的一次性短时凭证，兑换后按现有 Auth.js 机制建立网页会话，并跳转到报告地址。若内嵌方案无法上线，小程序原生页仍可打开已保存的报告。
- **电脑网页。** 使用同一智链账号登录后，在承接入口看到刚保存的快检报告，从该报告进入完整官网诊断。电脑端沿用现有登录方式，不依赖移动端会话或复制登录链接。
- **项目归属。** 保存快检先落在个人账号下。启动完整诊断时，用户确认目标项目和工作区，服务端核对权限并复用现有项目及诊断能力。现有获客激活路由会启动正式分析，报告保存需独立于该动作。

依据：[现有获客激活流程](../../src/app/api/acquisition/activate/route.ts#L27)、[智链网页会话配置](../../src/lib/auth/config.ts#L7)、[腾讯云小程序业务域名指南](https://cloud.tencent.com/document/product/1301/100434)。

## 验收与引流指标

- 验收匿名快检、拒绝或中断授权后的恢复、手机号新开户、已有账号关联、历史公众号账号、身份冲突、重复提交，以及小程序和电脑网页能否打开同一份已保存结果。
- 访客快检覆盖公开静态页、依赖 JS 的页面、不可访问页面等样本。记录有效结果率、单次成本和 P90 耗时，初始目标是 90% 的检测在 20 秒内给出可用结果。
- 用同一诊断标识串联「打开小程序 → 查看快检 → 完成身份验证 → 保存报告 → 开始完整诊断或提交有效品牌实测申请」。渠道按公众号、社群和用户转发归因。
- 同时看「已查看结果用户的账号验证完成率」和「已查看结果用户的实际后续使用率」。单列新注册、老账号绑定和返回用户。后续使用以完整诊断启动或有效品牌实测申请为准。

## 实施前确认

1. 在微信后台确认企业主体、小程序 AppID、手机号能力、服务类目与请求域名。若采用内嵌网页，确认业务域名和 iOS、Android 的真机承接表现。
2. 核实上游官网分析可独立复用的检查项，测算公开快检的耗时和成本。公开抓取需控制目标范围、单任务资源和并发。
3. 用一个已有手机号账号、一个历史公众号账号和一个新用户完成端到端验证，再确定账号绑定与诊断承接的实现排期。后端继续走智链既有 PR、CI 和发布流程，小程序走微信体验版及提审。
