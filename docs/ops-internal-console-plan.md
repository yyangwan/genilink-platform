# 运营中心独立后台修正方案

状态：按方案实施（2026-09-27）

## 目标与边界

`/ops` 承载智链团队自己的获客与销售运营。客户工作台只呈现客户购买和使用的功能。首版继续使用 `https://genilink.cn/ops`，无需新域名、独立服务或数据迁移。

| 区域 | 页面 | 入口 |
| --- | --- | --- |
| 客户工作台 | 智见、智创、内容洞察、项目、账单等 | 现有产品侧边栏 |
| 内部运营后台 | 获客转化、合作线索及线索详情 | 内部专用 `/ops` 地址和独立导航 |

## 具体改动

1. 从 `src/components/sidebar/sidebar.tsx` 删除“运营中心”区块及 `showOps` 属性；从 `src/app/(dashboard)/layout.tsx` 删除只为这个菜单而做的用户角色查询。产品菜单对管理员和客户保持同一套信息架构。
2. 将 `src/app/ops/layout.tsx` 改为独立的内部后台布局。后台页头明确标注“智链内部运营”，提供“获客转化”“合作线索”两个导航项、当前账号和“返回产品工作台”链接。后台不加载客户项目选择器、工作区状态、项目向导或产品侧边栏。
3. `/ops` 继续跳转 `/ops/conversion`。保留现有页面路径、查询、线索操作和企业微信通知里的详情链接，避免额外迁移。
4. 在后台入口检查登录状态和运营角色，但不把布局检查当作唯一权限边界。每个读取线索或转化数据的页面、`/api/ops/*` 接口和写入操作继续调用 `requireOps()`；`/api/ops/users/*` 继续要求 `requireAdmin()`。未登录用户进入登录页并返回原地址；普通账号的页面拒绝访问，接口返回 HTTP 403。
5. 从产品 `ContextBar` 移除仅为 `/ops` 加入的面包屑和项目选择器特判。`/content/insights` 保留在智创，因为它展示客户自己的项目数据。

## 权限状态码的实现选择

当前 Next.js 版本的 `forbidden()` 需要启用实验性 `authInterrupts`。建议本轮不增加实验配置：浏览器中的无权访问页面使用 `notFound()` 返回 HTTP 404，以减少内部路径暴露；`/api/ops/*` 继续返回准确的 HTTP 403。页面可在内部导航中避免出现无权限链接。若业务要求浏览器页面必须显示专门的 403 页面，再单独评估启用实验能力。

## 验收

- 管理员打开客户工作台时，看不到“运营中心”；智创中的“内容洞察”仍可用。
- 运营账号直接打开 `/ops`，进入独立后台；两个运营页面和线索详情均可导航，手机和桌面宽度可用。
- 未登录用户访问 `/ops`、线索详情时跳转登录；普通账号无法读取后台页面、接口或线索联系人字段。
- 运营账号不能调用仅管理员可用的角色管理接口。
- 产品工作区请求和项目向导不再因访问 `/ops` 而加载。
- 源码检查、测试、构建通过；若发布，按仓库规定经 PR、CI 和蓝绿流水线部署，并核对生产健康与回滚槽位。

- `src/app/(dashboard)/layout.tsx`
- `src/app/ops/layout.tsx`
